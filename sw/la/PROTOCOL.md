# Протокол S9LA (версия 1)

TCP, порт **5555**, один клиент. Клиент шлёт текстовые команды (строка, `\n`),
устройство отвечает кадрами:

```
смещение  размер  поле
0         2       'S' '9'
2         1       тип: 'R' ответ, 'H' заголовок захвата, 'D' данные, 'E' конец захвата
3         1       0
4         4       длина данных, little-endian
8         ...     данные
```

`R`, `H`, `E` — ASCII-текст. `D` — выборки подряд, `unit` байт на выборку, little-endian,
бит N = канал N. Длина `D` всегда кратна `unit`.

## Команды

| Команда | Ответ `R` |
|---|---|
| `ID` | `S9LA 1 channels=28 clock=100000000 memory=<байт>` |
| `CONF rate=<Гц> unit=<1\|2\|4> samples=<N> pre=<N> tmask=<hex> tval=<hex> trise=<hex> tfall=<hex> pattern=<0\|1\|2>` | `OK rate=<фактическая> samples=<N>` или `ERR <причина>` |
| `START` | `OK`, затем после окончания захвата: `H`, `D`…, `E` |
| `STOP` | без ответа: захват завершается досрочно (или прерывается выгрузка), затем `H`/`D`/`E` как обычно |
| `INPUT` | `OK <hex>` — текущие уровни входов |
| `PING` | `OK` |

`pattern`: 0 — входы, 1 — счётчик вместо входов (проверка тракта), 2 — входы + меандры на TX J1..J9.

`CONF` можно опускать отдельные ключи — остаются прежние значения.
Триггер: все условия по И; пустые маски — захват без ожидания.
`pre` — сколько выборок из `samples` идёт до триггера.

## Захват

```
→ CONF rate=10000000 unit=1 samples=1000000 pre=100000 tmask=0 tval=0 trise=1 tfall=0
← R "OK rate=10000000 samples=1000000"
→ START
← R "OK"
   … ожидание триггера и захват в DDR …
← H "samples=1000000 trigger=100000 unit=1 rate=10000000"
← D … (сколько угодно кадров)
← E "OK"                       или  E "ERR overflow" / E "OK aborted"
```

`trigger` — номер триггерной выборки в отправляемом потоке, `-1` — триггера не было
(захват остановлен командой `STOP`, отправлены последние выборки).

## Каналы

| Бит | Сигнал | Бит | Сигнал |
|---|---|---|---|
| 0–8 | RX хешплат J1..J9 | 18–23 | SPEED вентиляторов FAN1..FAN6 |
| 9–17 | PLUG хешплат J1..J9 | 24–27 | SCL1, SDA1, SCL2, SDA2 |
